CDS-Callbook — 一本公开的预测账本：在答案揭晓之前，先把话撂下。

> [!IMPORTANT]
> **这是模拟账本，仅供公开记录与校验，不涉及任何真实下注、不涉及一分钱。**
> 本仓库不输出投资建议，不暗示任何资金收益或损失。所有内容仅为判断力的长期自证。

一句话：我们把对公开预测市场问题的 Yes/No 判断提前写下来，等官方结算后再回来对账，然后公开统计命中率。

## 为什么做这本账本

我们做了一本公开的"预测账本"。

事情的起点其实很简单。像 Polymarket、Kalshi 这样的预测市场平台上，每天都有成千上万个关于选举、产品发布、各种还没发生的事的押注——人们用真金白银，买卖"这件事会发生"还是"不会发生"的合约。每一个这样的问题，到最后都会有一个官方揭晓的答案：发生了，或者没发生。我们一直想弄明白一件事：如果把自己对这些问题的是非判断，老老实实写下来，等结果出来再回头对账，时间长了，到底准不准？

很多人不敢这么做。因为"马后炮"太容易了——答案揭晓之后再表态，谁都能说自己猜对了。所以我们给自己定了一条规矩：判断必须在结果出来之前，公开写上，一字不改，只增不减。

这就是为什么它叫"账本"。每一笔预测，都是一条独立的记录：什么问题、我们押"是"还是"否"、写下的时间。等市场结算，我们再回来，在这一笔下面补上真实的答案，然后标记它对还是错。从第一笔到最新一笔，全按时间排着，谁都能翻。

你可能会问：怎么证明你真的是提前写的，不是事后补的？最直白的证明就在你眼前——每一笔预测，都会在答案出来之前，先出现在这个公开的仓库里，带着写下的日期，此后一直躺在那里，只会被追加，不会被改动。另外，我们每写一笔都会留一份版本提交记录，提交的那一刻，系统就盖上了时间戳。我们不玩花哨的把戏：公开、留痕、不改。

那这本账本怎么看？它就在我们的公开仓库里，谁都能打开。你进来会看到一列预测：每一条都对应公开市场上正在交易的一个问题，写着"我们押是还是否、写下的日期"。市场官方一结算，我们就用那个官方结果回来对账，标出这一笔对还是错。从第一笔翻到最新一笔，全程摊开，没有藏起来的，也没有被删掉的。你甚至可以不时回来看看——新预测总在答案揭晓之前冒出来，旧的那几行，从写下那天起就没动过。

你大概还会想：你嘴上说"写于某天"，我凭什么信那个日期？道理不复杂。账本上的每一笔，背后都是一次提交记录——我们把它交到版本库的那一刻，系统就记下了当时的时间，这个时间是改不了的。公开仓库里的内容，正是从这些提交记录里一点点长出来的。所以你看到的日期，不是我们事后填的，而是那条记录真正诞生的时间。我们不做"先有答案、再补日期"这种事，因为那样做，提交记录会对不上，一查就露馅。

最后说清楚一件事：这是一本"模拟账本"。里面没有任何真实的下注，不牵涉一分钱，我们也不给任何人投资建议。它更像一份长期的自证——我们到底有没有判断力，时间会替我们回答。

## 这本账本能做什么

| 提前写下判断 | 官方结算对账 | 命中率公示 |
|---|---|---|
| 在答案揭晓前，把对每个问题的 Yes/No 判断写入公开账本，带上时间戳。 | 市场官方公布结果后，用官方答案逐条核对，标记对错。 | 统计并公开总体命中率与分类命中率，样本不足时会明确提示。 |

## 我们的几条规矩

1. **只提前写，不事后补**：每条判断必须在官方结算前进入仓库，提交时间戳不可篡改。
2. **只追加，不修改**：`public-ledger/predictions/` 目录下的记录 append-only；修正须新增记录，原记录保留。
3. **只报命中率，不报收益**：公开侧只有命中率，不出现任何金额、收益率、PnL 等暗示真实盈亏的字段。
4. **结算只看官方**：每条记录的 actual 必须来自市场官方结算页或公开可读接口，不自判胜负。
5. **模拟盘，不下单**：本仓库仅为记录与展示，不连接任何交易接口，不进行真实或模拟下单。

## 仓库结构

```text
cds-callbook/
├── public-ledger/
│   ├── predictions/      # 预测记录（YYYY-MM-DD.jsonl，append-only）

│   └── accuracy.json     # 总体与分类命中率

├── tests/                # pytest 测试
├── tools/
│   └── gauntlet.sh       # 本地全关卡命令
└── .github/workflows/
    ├── test.yml            # pytest + schema 校验
    ├── guard-append-only.yml  # predictions/ 只增不改守卫
    └── pages.yml           # GitHub Pages 部署
```

## 三条不变式

1. **跨仓传输只有 6 字段**：`{id, question, call, commit_ts_utc, status}`，不携带置信度、赔率、数据源或任何方法痕迹。
2. **预测不可篡改**：`predictions/` JSONL append-only；修正须新增记录，拒绝编辑已存在行。
3. **存证 = git commit + GitHub push 时间戳**：README 顶部免责声明不可删除。

## 字段说明

- **预测记录**：`{id, question, call:"YES"|"NO", commit_ts_utc, status:"open"}`
- **结算记录**：`{id, actual:"YES"|"NO", correct:bool, resolved_ts_utc, resolution_source}`
- **命中率**：`accuracy.json` 中的 `rate` 字段；当 `total < 30` 时，页面会显示 `N=<n>` 并提示"样本不足，不具统计意义"。
